### 修复的真实缺陷
1. **洞府加成断链（核心）**：`CaveService.getCaveBonus()` 计算了
   `pill_success_bonus` / `tool_success_bonus`，但**全代码库零调用者**。
   玩家把丹房升到 10 级对炼丹成功率影响为 0。已在 `CraftingService.calcCaveBonus()` 接通。
2. **成功率公式与注释不符**：原代码仅 `base + skill_bonus`，境界只做 `>=` 硬门槛，
   不参与概率。已实现 `calcRealmModifier()`（正差加成/负差惩罚，双向封顶）。
3. **`skill_level_up` 恒为 false**：先覆写 `playerRecipe.skill_level = newLevel` 再比较
   `newLevel > playerRecipe.skill_level`。已用 `previousLevel` 留存旧值修复。
4. **数量上限双头维护**：硬编码 `quantity > 10` 与配置 `max_craft_quantity` 并存，已统一读配置，
   并补 `Number.isInteger` 校验拦截小数/NaN。
5. **`_clampRate` 的 Infinity 缺陷**：`Number.isFinite(Infinity)===false` 导致 Infinity
   被当作 NaN 返回下限。**此缺陷由测试用例捕获**，已改为仅对 NaN 兜底。

### 新增功能
- **火候控制玩法**：`craftStart`/`craftHeat`/`craftFinish`/`craftCancel`/`getHeatSession`。
  服务端生成各阶段目标火候但**不下发答案**，只给模糊"灵火征兆"提示。
  反作弊：同玩家仅保留一个会话（防择优提交）；`craftFinish` **先删会话再炼制**（防并发重复结算）。
  内存会话 Map + `unref()` 定时清扫器防泄漏（`stopSessionSweeper()` 供测试关闭）。
- **丹药品质浮动**：偏差 → 劣品/凡品/上品/极品/完美，技能等级提供偏差容错。
- **auto 一键模式**：保留旧玩法路径，代价是固定成功率惩罚 + 中档品质。
